# Establish design tokens

Inspect existing Figma variables, styles, code, and libraries when supplied and accessible. Reuse an established system. If none exists, label any proposed palette, typography, spacing, radius, and motion choices as proposals tied to this product and the owner's design taste.

Document semantic names, values, units, source, theme, and actual component use in the project's tokens file. Do not infer a production system from historical screenshot samples or force a new stack, dark theme, or token scale onto an existing product.

For a mismatch, compare exported values with code references, hardcoded overrides, units, zoom, and rendering context. Test a representative binding before claiming instances update together. Verify relevant contrast and interaction requirements from the applicable standard; distinguish a recommended target from a normative requirement.

Missing sources or untested bindings remain explicit. Do not fill Styra's status document with invented values.
