# Diagnose a blocker

Inspect the request, active folder, current Git status, relevant instructions, dependency files, and recent log before asking the owner to explain everything again. Check whether a source is missing, a file is a template, a path is wrong, or a skill has not been discovered.

Use the shortest evidence-based diagnosis. Attempt ordinary authorized, reversible repairs directly. Do not reset user work, disable security, overwrite source designs, or change product scope to make progress. An unfilled template is not proof that the user is behind or that a tool is broken.

Verify a repair. If blocked after reasonable recovery, explain the concrete cause, what was tried, and the single minimum user action or piece of evidence needed. Do not assume the course, account, or operating system caused a fault without evidence.
