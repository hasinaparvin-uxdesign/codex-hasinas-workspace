# Develop a design brief

Read all supplied brief versions, project context, engagement, agreement, and any requirements handshake together. Separate source statements, confirmed owner decisions, working hypotheses, and open conflicts. Do not promote an older draft or a facilitator example to an approved requirement.

When brief development is authorized, use a named clarified-brief target while preserving original sources. Cover the problem and context, user task, design direction, functional needs, constraints, and observable success criteria. Metrics need a stated source or must be proposed validation measures, not invented outcomes or commitments.

Reuse known answers. Ask only about gaps that change the solution, and leave unresolved consequential scope choices open. Write authorized changes directly and report the target and status. Styra brief work remains deferred until the owner resumes it.
