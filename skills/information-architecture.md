# Map the information architecture

Read the approved scope, available brief, context, and agreements. Identify material uncertainties before committing to a flow. Begin with what the person does and decides, including entry, alternatives, cancellation, failure, and completion; then derive screens and states.

Write a project IA document with journey, screen-to-step mapping, navigation, and content hierarchy. Report screens with no supported step, steps with no screen, and steps that intentionally happen outside the product. Do not add checkout, voice, or other deferred capabilities simply because another project had them.

When a visual companion is useful, create a matching HTML/CSS page or supported diagram without making it the only source of the mapping. Verify labels, connections, reading order, overflow, and narrow-screen behavior in a browser. Report if that verification is unavailable. Keep the text and visual in agreement.
