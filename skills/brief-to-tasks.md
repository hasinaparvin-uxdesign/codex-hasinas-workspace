# Plan the work

Read the brief, context, scope, IA, existing system, and current implementation. Reuse adequate completed work. If a gap changes the task plan materially, resolve it or label the dependent task blocked instead of silently selecting a product direction.

Create or update a project task checklist grouped as foundation, structure, build, and review where useful. Each task needs an action, dependency, and observable done-when condition. Include relevant loading, empty, error, long-content, responsive, and accessibility work as actual tasks.

Avoid invented delivery promises or fixed estimates without a basis. Identify parallel work only when dependencies permit it. Task completion requires its stated evidence; generating a checklist does not implement the product or approve scope.
