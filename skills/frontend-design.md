# Build the agreed interface

Inspect the current code, applicable instructions, approved task, brief, context, and design sources. Reuse existing components and tokens. Resolve missing inputs that materially affect the implementation; do not invent an approved brief, library, or stack.

Build the named task with semantic structure, purposeful hierarchy, appropriate states, keyboard access, responsive behavior, and the owner's product-specific taste. Reuse established token names and mark new proposed choices when needed. An HTML starter is only a prototype unless the project requires otherwise; do not force a single-file output onto a real application.

Run the relevant build, behavior, and visual checks supported by the project. Check representative viewport and content extremes, and report unverified items. Do not call code production-ready merely because it renders. Preserve source designs and defer substantive product changes to the owner.
