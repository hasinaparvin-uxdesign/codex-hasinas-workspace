# New project template

**Status: template, not an active project.** Ask Codex to duplicate this folder into a named sibling under projects when starting a new project. Keep this template unfilled.

| File | Purpose |
| --- | --- |
| [context.md](context.md) | Confirmed user, problem, environment, evidence, and unknowns |
| [codex-contract.md](codex-contract.md) | This project's owner, safeguards, and settled constraints |
| [engagement.md](engagement.md) | Deliverables, exclusions, approval, changes, and any agreed commercial limits |
| [brief-interrogated.md](brief-interrogated.md) | Handshake and clarified brief after authorized scope work |
| [critique-notes.md](critique-notes.md) | Findings, evidence, owner decisions, and implementation status |
| [tokens.md](tokens.md) | Actual design-system sources, semantic values, and verified bindings |
| [log.md](log.md) | Session handoff |
| [screen.html](screen.html) | Clearly labelled, nonfunctional screen starter |

Read the shared [working agreement](../../principles/codex-contract.md), [design taste](../../principles/design-taste.md), and [anti-slop rules](../../principles/anti-ai-slop.md). Use the [workflow index](../../skills/README.md) for relevant steps.

Capture known context before generation and agree engagement boundaries before making a quote or delivery commitment. Unknown answers remain unknown. Tokens, IA, tasks, and prototypes should be developed when the actual assignment needs them, not filled with invented requirements. Existing projects keep their historical brief and review names.
